Android engineering source registry

This registry identifies official upstream sources; it stores metadata and retrieval rules, not copied documentation. Authority labels describe source role: A1 normative documentation or release records; A2 implementation source; A3 illustrative sample code. An A3 sample never overrides A1 documentation. For every answer, report the exact page, artifact version, tag, or commit consulted. The repository build files and tests determine the project’s declared baseline; this registry sets none.

## Retrieval and conflict rules

Start with the user’s concrete question and the project’s declared tool/library versions. Retrieve only the matching topic, artifact, source path, or sample. Prefer exact-version A1 documentation for normative/API claims; use A2 source to explain observed implementation details and A3 samples only as examples. When guidance conflicts, first compare versions, API level, scope, and page dates; cite each relevant source and state unresolved disagreement instead of silently blending claims. Record provenance as canonical URL plus page heading or artifact, access/check date, and exact version/tag/commit. Freshness is per consultation; this registry does not run a polling service or mirror upstream content.

## Baseline and boundaries

No Android application or build files are present in the repository at registry creation, so no Android, Kotlin, Gradle, Compose, Material 3, or AndroidX version baseline is declared. This registry contains source metadata and retrieval policy only. Do not bulk-import documentation or clone AndroidX for routine research.
